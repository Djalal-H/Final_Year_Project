---
description: Generate a concise yet comprehensive context file summarizing the current development phase. This document should serve as a reference for the project's current state, capturing high-level goals, design decisions, and implementation progress.
---

1.  **Phase Overview:**
    *   Briefly name and define this development phase or milestone.
    *   Clearly state the **primary objective** or functional outcome this phase aims to achieve.

2.  **Theoretical Foundation & Design Goals:**
    *   Summarize the core problem statement or user need being addressed.
    *   Outline the **key principles, architectural patterns, or design paradigms** guiding the work. Explain *why* these were chosen.
    *   Describe the **intended system behavior**.

3.  **Implementation Summary:**
    *   Provide a high-level **technical overview** of what was built or modified.
    *   List the **main components, modules, or services** that were the focus, describing their purpose in simple terms.
    *   Highlight any **significant integrations** 

4.  **Key Decisions & Rationale:**
    *   Explicitly document **major technical or design choices** made during this phase.
    *   For each choice, provide a clear, positive **justification** based on factors like:
        *   Requirements fit
        *   Best practices or industry standards
        *   Future extensibility
        *   Team expertise or consistency with the existing codebase
        *   Performance or security considerations

**Critical Style Guidelines:**

*   **Tone:** Write in a clear, neutral, and professional tone. Focus on what *was done* and *why*, not on obstacles.
*   **Omission Directive:** Do **not** mention errors, bugs, debugging processes, or specific challenges faced during implementation. This document should reflect the finalized state and intentional decisions.
*   **Detail Level:** Keep explanations technical but accessible. Avoid deep code snippets or overly granular details. Assume the reader is a technical stakeholder familiar with the project domain but not necessarily with day-to-day code.
*   **Focus:** Frame everything in terms of progress made, solutions implemented, and rationale for the chosen path.

**Output Format:** Present the summary in a well-structured, readable format suitable for a markdown (`.md`) or text file.
